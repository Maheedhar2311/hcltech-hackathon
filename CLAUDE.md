# HCLTech Hackathon Project

## Objective
Build a reliable, working solution for the HCLTech hackathon case study.

## Team
There are four team members working collaboratively on one laptop.

Each module must have a designated owner. Every team member must understand their own module and the overall architecture.

## Development rules
1. Analyse the case study before writing code.
2. Separate stated requirements from assumptions.
3. Research possible approaches and justify the chosen solution.
4. Design the architecture before implementation.
5. Define module interfaces before developing components.
6. Implement incrementally, one module at a time.
7. Write and execute tests throughout development.
8. Do not claim tests passed unless they were actually run.
9. Do not invent evaluation results.
10. Explain important code and design decisions in simple language.
11. Avoid unnecessary features and dependencies.
12. Do not expose API keys or credentials.

## Team collaboration
Every task must have an owner and clear acceptance criteria.

Before modifying files, explain the planned changes.

Avoid modifying another member's module without coordination.

After implementation, explain the code, report actual test results, and identify limitations.

## Hackathon priorities
Prioritise a working end-to-end solution, requirement coverage, meaningful testing, and measurable improvements.

Do not assume the technology stack before analysing the case study.
